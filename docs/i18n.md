# Internationalization (i18n) Setup

This project supports multiple languages using `react-i18next` and `i18next`. Currently supported languages:
- English (en)
- Vietnamese (vi)

## Features

✅ **Client-side i18n** - Works with Next.js App Router  
✅ **Language detection** - Automatically detects user's preferred language  
✅ **Language persistence** - Saves language preference in localStorage  
✅ **Language switcher component** - Easy switching between languages  
✅ **Type-safe translations** - Custom hook for better developer experience  
✅ **Centralized language metadata** - All language info in dedicated types file  
✅ **Utility functions** - Helper functions for language operations  
✅ **Automatic detection** - Languages automatically appear when added

## File Structure

```
public/locales/
├── en/
│   └── common.json          # English translations
└── vi/
    └── common.json          # Vietnamese translations

lib/
└── i18n.ts                  # i18n configuration

types/
└── language.ts              # Language types and metadata

components/
├── providers/
│   └── i18n-provider.tsx    # i18n context provider
└── language-switcher.tsx    # Language switcher UI component

hooks/
└── use-translation.ts       # Custom translation hook
```

## Usage

### 1. Using the translation hook

```tsx
import { useTranslation } from '@/hooks/use-translation';

export function MyComponent() {
  const { t } = useTranslation();

  return (
    <div>
      <h1>{t('app.name')}</h1>
      <p>{t('app.description')}</p>
    </div>
  );
}
```

### 2. Adding new translations

Add your translation keys to the respective JSON files:

**English (`public/locales/en/common.json`):**
```json
{
  "my_new_key": "Hello World"
}
```

**Vietnamese (`public/locales/vi/common.json`):**
```json
{
  "my_new_key": "Xin chào thế giới"
}
```

### 3. Using language utilities

The app provides utility functions for working with languages:

```tsx
import { 
  getAllAvailableLanguages, 
  findLanguageByCode, 
  getLanguageDisplayName,
  getLanguageFlag 
} from '@/lib/language-utils';

export function MyComponent() {
  // Get all available languages
  const languages = getAllAvailableLanguages();
  
  // Find specific language
  const french = findLanguageByCode('fr');
  
  // Get display info
  const displayName = getLanguageDisplayName('vi'); // "Tiếng Việt"
  const flag = getLanguageFlag('en'); // "🇺🇸"
  
  return (
    <div>
      {languages.map(lang => (
        <span key={lang.code}>
          {lang.flag} {lang.name}
        </span>
      ))}
    </div>
  );
}
```

The `LanguageSwitcher` component is already integrated into:
- Home page navigation
- Dashboard layout
- Can be added to any component

```tsx
import LanguageSwitcher from '@/components/language-switcher';

export function MyLayout() {
  return (
    <div>
      <nav>
        <LanguageSwitcher />
      </nav>
    </div>
  );
}
```

## Adding New Languages

1. Create a new directory in `public/locales/` (e.g., `fr` for French)
2. Add translation files following the same structure as existing ones
3. Add language metadata to `types/language.ts`
4. Import and add the resources in `lib/i18n.ts`

The language switcher will automatically detect and display all available languages.

Example for adding French:

```typescript
// lib/i18n.ts
import frCommon from '../public/locales/fr/common.json';

const resources = {
  en: { common: enCommon },
  vi: { common: viCommon },
  fr: { common: frCommon }, // Add this
};
```

```typescript
// types/language.ts
export const languageMetadata: Record<string, LanguageMetadata> = {
  en: { name: 'English', flag: '🇺🇸' },
  vi: { name: 'Tiếng Việt', flag: '🇻🇳' },
  fr: { name: 'Français', flag: '🇫🇷' }, // Add this
};
```

## Translation Keys Structure

The current translation structure includes:

- `app.*` - Application metadata (name, description)
- `navigation.*` - Navigation menu items
- `common.*` - Common UI elements (buttons, labels, etc.)
- `forms.*` - Form field labels and placeholders
- `auth.*` - Authentication related text
- `quiz.*` - Quiz-specific terminology
- `dashboard.*` - Dashboard specific content
- `settings.*` - Settings page content
- `messages.*` - Error messages, notifications

## Best Practices

1. **Use descriptive keys**: Instead of `button1`, use `common.save_button`
2. **Group related translations**: Use namespaces like `auth.*`, `quiz.*`
3. **Keep translations short**: Long text should be split into multiple keys
4. **Use interpolation for dynamic content**: `"welcome_user": "Welcome {{name}}!"`
5. **Test with longer languages**: Some languages like German can be much longer

## Configuration

The i18n configuration is set up in `lib/i18n.ts` with:
- Language detection from localStorage, navigator, and HTML tag
- Fallback to English if translation is missing
- No suspense mode for better App Router compatibility
- Caching in localStorage for persistence

## Browser Support

This setup works in all modern browsers and gracefully falls back to English for any missing translations or unsupported environments.
